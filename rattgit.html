Rätt Git-repo i Cursor

Vad som hände, vad som gjordes, och vad du ska tänka på i framtiden

1. Vad som hände – problemet förklarat

Den 8 juni 2026 skapades ett nytt git-repo inne i Ekonomi-mappen. Det var rätt beslut – Ekonomi fick ett eget GitHub-repo. Men det uppstod ett klassiskt problem: nested repo (inbäddat git-repo).

Mappstrukturen ser ut så här

C:\Users\kentl\OneDrive\AI\Claude\ ← HAR .git (repo: Ovrigt) ├── ArbetenSokta\ ├── ClaudeCowork\ ├── Ekonomi\ ← HAR EGET .git (repo: Ekonomi) │ ├── .git\ ← Ekonomis eget git-repo │ ├── index.html │ └── redovisning\BAS\analys.html └── Ovrigt\

Ekonomi-mappen har ett eget .git, men ligger inuti en annan mapp (AI\Claude) som också har ett .git. Det kallas nested repo.

Varför visade Cursor fel repo?

När Cursor öppnar en mapp letar den efter .git – inte bara i den öppnade mappen, utan också uppåt i mappstrukturen. Cursor hittade föräldramappens .git (vid AI\Claude) och visade det repots git-status i Source Control-panelen.

Konsekvensen: Source Control-panelen visade ändringar från ArbetenSokta, ClaudeCowork, Ovrigt m.fl. – filer som inte alls tillhör Ekonomi-projektet. Om Kent hade klickat "✓ Commit" i GUI:t hade det committat till fel repo (Ovrigt på GitHub), inte till Ekonomi.

2. Vad som gjordes – de två åtgärderna Löst 2026-06-08

ÅtgärdFilEffekt
1. Workspace-inställning Ekonomi\.vscode\settings.json Cursor ignorerar föräldra-repot när Ekonomi är öppet
2. Gitignore-tillägg AI\Claude\.gitignore Föräldra-repot slutar spåra filer i Ekonomi-mappen

Åtgärd 1 i detalj – .vscode\settings.json

En ny fil skapades: C:\Users\kentl\OneDrive\AI\Claude\Ekonomi\.vscode\settings.json 

{
  // Talar om för Cursor: "ignorera föräldramappens git-repo
  // när du arbetar i Ekonomi-workspacet."
  "git.ignoredRepositories": [
    "C:\\Users\\kentl\\OneDrive\\AI\\Claude"
  ]
}

Inställningen är workspace-specifik – den gäller bara när Ekonomi-mappen är öppnad i Cursor. Andra mappar påverkas inte.

Effekt: Cursors Source Control-panel visar nu enbart Ekonomi-repots ändringar. Commit-knappen i GUI:t arbetar mot github.com/kentlundgren/Ekonomi.

Åtgärd 2 i detalj – föräldra-repots .gitignore

Följande rad lades till i C:\Users\kentl\OneDrive\AI\Claude\.gitignore: 

# Ekonomi har eget git-repo och egen GitHub – ignoreras här
Ekonomi/

Föräldra-repot (Ovrigt på GitHub) slutar nu se och spåra filer inuti Ekonomi-mappen. Det är rent och logiskt – Ekonomi lever sitt eget liv.

3. Så commitar och pushar du i Cursor (efter omstart)

När Cursor startas om med Ekonomi-mappen öppnad gäller .vscode/settings.json och Source Control visar rätt repo. Då kan du använda GUI:t direkt:

  1. Öppna Source Control-panelen: klicka på gren-ikonen i vänster sidofält, eller tryck Ctrl+Shift+G.
  2. Kontrollera att det i listan bara syns filer från Ekonomi-projektet (index.html, analys.html, README.md osv.) – inga filer från ArbetenSokta eller ClaudeCowork.
  3. Skriv ditt commit-meddelande i textrutan överst i Source Control-panelen.
  4. Klicka "✓ Commit" (eller Ctrl+Enter).
  5. Klicka "Sync Changes" (eller "Push") för att föra över till GitHub.

Dubbelkolla alltid statusfältet längst ner i Cursor. Det ska stå "main" (eller aktuell branch) och inte "Claude" (föräldramappens namn). Om det står "Claude" har Cursor inte laddat workspace-inställningen – starta om Cursor och försök igen.

Terminalen som backup

Om GUI:t mot förmodan skulle bete sig konstigt, öppna terminalen (Ctrl+Ö) och kör: 

cd "C:\Users\kentl\OneDrive\AI\Claude\Ekonomi"
git remote -v            # Ska visa: origin → Ekonomi.git
git status               # Ska bara visa Ekonomi-filer
git add .
git commit -m "Ditt meddelande"
git push

4. Tänk på detta i framtiden Viktigt

  • Kontrollera alltid statusfältet längst ner i Cursor innan du commitar. Det ska visa rätt repo-namn och branch. Om det visar fel namn – stäng och öppna rätt mapp, eller starta om Cursor.
  • Öppna alltid rätt mappnivå i Cursor. Om du öppnar AI\Claude (föräldermappen) istället för Ekonomi ser du föräldra-repots Source Control igen. Öppna alltid Ekonomi-mappen direkt: File → Open Folder → välj Ekonomi.
  • Nytt projekt i framtiden? Om du skapar ett nytt eget repo (t.ex. AI\Claude\NyttProjekt) och det projektet också får en eget GitHub-repo, upprepa samma två åtgärder:
    1. Skapa NyttProjekt\.vscode\settings.json med git.ignoredRepositories pekande på föräldermappen.
    2. Lägg till NyttProjekt/ i föräldermappens .gitignore.
  • Starta om Cursor efter att settings.json skapats. Cursor laddar workspace-inställningar vid start. En ny .vscode/settings.json får full effekt först efter omstart.
  • Undvik att committa från föräldramappens Source Control. Om du öppnar AI\Claude och ser Ekonomi-filer där – committa INTE via den panelen för Ekonomi-filer. Det hamnar i fel repo (Ovrigt). Gå istället till terminalen och cd till rätt mapp.
  • En snabb sanity check: git remote -v i terminalen från rätt mapp visar alltid exakt vilket GitHub-repo du är kopplad till. Kör det om du är osäker.

5. Bonusproblem: filerna visades som "ändrade" trots att de just committats

Direkt efter att nested repo-fixet pushades visade Source Control-panelen i Cursor 6 filer som modifierade – trots att vi precis committat och pushat dem. Ingenting i innehållet hade förändrats. Det berodde på ett klassiskt Windows-problem: LF vs CRLF.

Vad är LF och CRLF?

Alla textfiler – HTML, Markdown, JSON, kod – innehåller osynliga tecken som markerar radslut. Det finns två varianter:

SymbolNamnAnvänds av
LF Line Feed (\n) Linux, macOS, GitHub – det som git lagrar i repot
CRLF Carriage Return + Line Feed (\r\n) Windows – det som Notepad och många Windows-program förväntar sig

Vad hände konkret?

Git på Windows har en inställning (core.autocrlf) som automatiskt konverterar radbrytningar: LF → CRLF när filer hämtas från repot till din dator, och CRLF → LF när de skickas tillbaka. Filerna i repot (på GitHub) har LF. Din lokala kopia på Windows fick CRLF. Git jämförde dem och såg skillnad – trots att innehållet i praktiken var identiskt.

Varför visades git diff som tomt trots att git status visade "modified"?
Därför att git diff normaliserar radbrytningar när det jämför – och hittade inga faktiska textskillnader. Men git status tittar på råa bytes i filen, och CRLF ≠ LF på byte-nivå.

Hur fixades det – .gitattributes Löst 2026-06-08

En ny fil skapades: Ekonomi\.gitattributes 

# Normalisera alla textfiler till LF i repot
* text=auto eol=lf

# Binärfiler – inga radbrytningskonverteringar
*.png binary
*.jpg binary
*.pdf binary

Sedan kördes kommandot: 

git add --renormalize .

Det kommandot tvingar git att skriva om alla filer i indexet med rätt radbrytningar enligt .gitattributes-regeln. Resultatet: de falska "modified"-markeringarna försvann direkt.

Effekt: Source Control-panelen visar nu 0 ändringar – repot är rent. Framöver konverteras inga radbrytningar automatiskt, och problemet uppstår inte igen för nya filer i detta repo.

Tänk på detta i framtiden

  • Inkludera alltid .gitattributes i nya projekt redan från start. Det är bästa praxis för alla projekt som ska fungera på både Windows och GitHub/Linux.
  • Om Source Control visar filer som "modified" utan synliga ändringar är det troligen ett radbrytningsproblem. Kör git diff – är det tomt är det CRLF/LF. Lösning: skapa .gitattributes och kör git add --renormalize .
  • Kontrollera alltid git status via terminalen om Cursor visar ändringar som känns konstiga. Terminalen ger den faktiska sanningen om repots tillstånd.

6. Sammanfattning – alla problem och lösningar

FrågaSvar
Vad är nested repo? En mapp med .git inuti en annan mapp som också har .git.
Varför visade Cursor fel repo? Cursor scannde uppåt i mappstrukturen och hittade föräldermappens .git först.
Hur fixades det? .vscode/settings.json med git.ignoredRepositories + Ekonomi/ i förälderns .gitignore.
Var är inställningen sparad? Ekonomi\.vscode\settings.json – finns i repot och gäller automatiskt.
Påverkas andra projekt av fixet? Nej – inställningen är workspace-specifik och gäller bara Ekonomi-mappen.
Har föräldra-repot fortfarande nytta? Ja – det spårar ArbetenSokta, ClaudeCowork och Ovrigt. Ekonomi är nu korrekt uteslutet.
Hur vet jag att jag är i rätt repo? Statusfältet visar rätt branch-namn UTAN "Claude". Kör git remote -v om osäker.
Varför visas filer som "modified" utan ändringar? LF/CRLF-konvertering på Windows. Fix: .gitattributes med eol=lf + git add --renormalize .
